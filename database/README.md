# Database

Single PostgreSQL database shared by **all four modules**. There is no
per-module database — the modules are separated by *code ownership*, not by
*data ownership*.

## Tables

| Table | Module / owner | Purpose |
| --- | --- | --- |
| `roles` | 1 — masterdata | Role definitions + `base_role` that drives the permission matrix |
| `users` | 1 — masterdata | Login accounts (bcrypt hash), FK to `roles` |
| `shifts` | 1 — masterdata | Shift definitions, `planned_minutes` = OEE planned production time |
| `items` | 1 — masterdata | Products, `standard_cycle_time` = ideal cycle time for OEE Performance |
| `machines` | 1 — masterdata | Machine master, `status` is a denormalised cache of the latest event |
| `abnormalities` | 1 — masterdata | Abnormality categories (breakdown, material problem, sensor error…) |
| `defects` | 1 — masterdata | Defect master used by NG events and the Pareto chart |
| `production_setups` | 1 — masterdata | Changeover/setup master with duration |
| `work_orders` | 2 — workorder | Daily/monthly work orders, approval workflow, target qty |
| `work_order_items` | 2 — workorder | Item lines of a work order (multi item support) |
| `production_logs` | 2 — production | Immutable event stream: one row per operator/MQTT action |
| `downtime_logs` | 2 — production | BREAK / ABNORMALITY / SETUP intervals |
| `oee_records` | 3 — oee | Materialised OEE per shift/day with all calculation inputs |

`analytics` (member 4) owns **no tables** — it only reads the tables above.
That guarantees "Analytics data = raw production data".

## Relationships

```
roles 1───* users
shifts 1───* work_orders *───1 machines
items  1───* work_orders *───1 items (work_order_items)
work_orders 1───* production_logs *───1 machines / items / shifts / users / defects
production_logs 1──0..1 downtime_logs
abnormalities 1───* downtime_logs
machines 1───* oee_records   shifts 1───* oee_records
```

## Setup

### Option A — NeonDB (recommended for the team)

1. Create a project at <https://console.neon.tech>.
2. Copy the **pooled** connection string, it looks like:
   `postgresql://USER:PASSWORD@ep-xxx-pooler.region.aws.neon.tech/andon?sslmode=require`
3. Put it into `backend/.env`:

   ```env
   DATABASE_URL=postgresql://...
   DB_SSL=true
   ```

4. Apply the schema and the seed data:

   ```bash
   npm run db:schema
   npm run db:seed
   npm run db:status   # verify
   ```

Neon already terminates TLS, so `DB_SSL=true` is used with
`rejectUnauthorized: false` (Neon uses a private CA).

### Option B — local PostgreSQL via docker compose

```bash
docker compose up -d db          # PostgreSQL 16 on localhost:5432
cp backend/.env.example backend/.env
npm run db:schema && npm run db:seed
```

### Reset everything (destroys all data)

```bash
npm run db:reset
```

## Conventions

* Primary keys: `UUID` generated by `gen_random_uuid()` (built into PostgreSQL 13+).
* Timestamps: `TIMESTAMPTZ`, always stored in UTC.
* Enumerations: `TEXT` + `CHECK` constraint instead of native `ENUM`, so values
  can be extended without `ALTER TYPE`. The values must stay in sync with
  `shared/src/constants/enums.ts`.
* `updated_at` is maintained by the `set_updated_at()` trigger.
* Money/quantity are `INTEGER`, ratios are `NUMERIC(7,4)` in the `0..1` range.
* Emails are stored lower-cased and validated by a `CHECK`.

## Changing the schema

`schema.sql` is a **coordinated file** (see `docs/collaboration.md`).

1. Propose the change in an issue/PR.
2. Keep `schema.sql` re-runnable: use `CREATE TABLE IF NOT EXISTS`, add new
   columns with defaults, never drop columns that another module reads.
3. When you add an enumeration value, update **both** `schema.sql` and
   `shared/src/constants/enums.ts` in the same PR.
4. Never create a second database for your module.

See `docs/database.md` for the column level reference and the OEE derivation.
